# 图标库视觉方向决策

document_state: accepted
decision_date: 2026-08-23

## 决策

RallyPair / 羽搭采用配色候选 B“天空与草地”，并保留当前五组信息结构：

1. 球场
2. 分组
3. 候场
4. 轮转
5. 结果

应用内语义图标统一使用圆润粗轮廓、大留白和局部实心强调；扩展新图案时优先保证 24px 尺寸下的识别度。

## 强制绘制规范

本规范适用于后续所有应用内图标的生成、修改、扩展和实现：

| property | constraint |
| --- | --- |
| coordinate system | `24×24` viewBox |
| stroke | `2.2px`，圆头、圆角连接 |
| safe area | 主体默认位于 `3–21px` 范围 |
| structure | 圆润粗轮廓、大留白、少量几何结构 |
| primary color | `#2563D9`，承担主体轮廓与识别 |
| accent color | `#3BBF75`，每个图标只用于一个局部实心焦点 |
| minimum check | 必须检查真实 `24px` 显示效果 |
| source format | 概念与源资产优先使用可编辑 SVG |

禁止默认引入：

- 细线、尖角、拟物质感或复杂插画细节。
- 大面积实心色块，或蓝绿两色平均争夺视觉焦点。
- 仅靠绿色区分进行中、成功、选中等业务状态。
- 与当前批次明显不同的笔画粗细、圆角半径或视觉重量。
- 未经确认覆盖现有已采纳 SVG。

新图标进入实现前必须同时满足：语义在无文字时可推断、24px 下清晰、与相邻图标不易混淆、与现有批次视觉重量一致。

当前规范样本：[`../work/icon_library/rally-pair-icon-batch-01.html`](../work/icon_library/rally-pair-icon-batch-01.html)。

## 变更流程

任何偏离上述规范的需求都视为图标系统变更，不作为普通单图调整处理。执行前必须：

1. 说明偏离原因、影响范围和与当前图标家族的差异。
2. 取得用户明确确认。
3. 更新本决策、HTML 图标墙和项目状态入口。
4. 重新检查 24px 显示、配色职责与相邻图标辨识度。

## 颜色职责

| token | value | responsibility |
| --- | --- | --- |
| background | `#EDF4FA` | App 主背景 |
| surface | `#FFFFFF` | 导航、卡片与浮层表面 |
| surface_soft | `#DDEAF2` | 选中态与弱分组背景 |
| text_primary | `#102A43` | 标题与主要内容 |
| text_secondary | `#526B7B` | 辅助说明与 metadata |
| primary | `#2563D9` | 品牌、主操作与当前导航 |
| accent | `#3BBF75` | 进行中与局部反馈，不单独表达状态 |
| court | `#2E9376` | 羽毛球场表面 |
| court_line | `#F8FFFC` | 场地标线 |
| danger | `#C23E55` | 错误与危险操作 |

高饱和色面积控制在单屏 10–15% 内。蓝色不兼任错误色，绿色状态必须同时使用文字、轮廓或位置表达。

## 球场结构

场地可视化使用标准羽毛球场关系，保留：

- 双打外边线
- 单打内边线
- 两侧短发球线
- 两侧双打后发球线
- 左右发球区中线
- 中央球网

移动端允许按容器压缩比例，但不得重新简化为均匀四分格。

## 选择理由

- 蓝色能稳定承担品牌与主操作，绿色能自然承接羽毛球场和运动状态，职责比其他候选更清楚。
- 冷白表面适合现场快速扫读，不会让大量分组和候场信息显得沉重。
- 真实场线、固定五组结构和圆润图标共同提供项目识别，避免退化为通用运动科技模板。

## 未采用候选

- A“球场清新”：绿色职责重叠，品牌、球场和状态容易互相稀释。
- C“比赛信号”：赛事提醒感过强，不适合作为日常约球与轮转工具的长期底色。
